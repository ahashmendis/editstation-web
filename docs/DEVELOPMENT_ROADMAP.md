**Constraints from Phase 4 for later phases** (spec §15):

- Phase 5: `project_references` already exists (admin-only); Phase 5 adds assets and editor visibility. Editor `select` policies cover `projects`, `project_deliverables`, `project_references` and `brief_versions` only, never `project_internal` or `clients`.
- Phase 6: `project_access` invitations only for projects with `first_opened_at is not null`; refuse `open → draft` once any `project_access` or assignment exists. Same editor `select` rule as Phase 5.
- Phase 7: `brief_confirmations.brief_version_id` is `on delete restrict`; confirmations are immutable and accepted only for the project's current version; carry-forward when `requires_reacknowledgement = false` is recorded as such; deadline and pay drift is detected from the values stored at confirmation.

**Public launch gates** (independent of phase numbers): P (retention and privacy notice), KB1
(entity), KB2 (brand and domain for site and email), KB8 (editor terms), O (captcha before the
forms go live), production SMTP.

Phases 2 and 3 are independent of each other once Phase 1 exists. A pilot after Phase 9 is
realistic, with Phase 10 run manually at first.
