Summary

All eleven roadmap phases are built and merged. What the system does

Three kinds of account: admin (MFA required), applicant and active editor. Clients never get an account; they reach the studio through a public inquiry form.

0–3

Foundation, access and public site

Sign-up and sign-in, admin MFA enforced in the database, editor applications and vetting, public landing page, rate-limited client inquiry form, admin inquiry inbox and settings.

4

Projects and briefs

Clients, projects, three brief types, versioned briefs that lock after first opening, deliverables and timestamped references. Only an admin can turn an inquiry into a project.

5–6

Assets, editor access and offers

Asset records (links, never files), tiered editor visibility, invitations, offers and counteroffers, confirmed assignments, reassignment and internal notes.

7

Confirmation gate

Editor interpretation, brief confirmation, and a database gate that blocks editing until pay is agreed, the brief is confirmed and both project and editor are active.

8

Submissions and review

Versioned submissions, admin approval or revision requests, and classification of each revision as a client round, editor correction or scope change. The 3 free client rounds are tracked.

9

Earnings

Payments created from assignments, admin approve, hold and mark-paid with transfer reference, and an earnings screen for each editor showing only their own payments.

10

Notifications and metrics

In-app notifications for 11 events with a bell and /notifications, an email queue (nothing is sent yet), metric cards on the admin dashboard and an activity log at /admin/activity.

11

Hardening

Signed-in browser tests, security headers, a local backup-and-restore drill, runbooks and an acceptance check against section 16 of the knowledge base.

Security and quality

  • Every database table has row-level security, with access denied by default. Each rule is tested as admin, editor A, editor B, pending applicant and signed-out visitor.
  • Editors cannot see client data, client prices, other editors' work or other editors' payments. Money and status changes go only through database functions.
  • Admin rights require an MFA session, checked inside the database, not only in the app.
  • Users only ever see safe error messages. No secret keys reach the browser.
  • Security headers block the site being framed by other pages.
  • CI on GitHub runs lint, typecheck, unit tests, the production build, all database tests and the browser tests on every push. All three jobs pass.

Going live

These steps need the owner's own accounts and keys.

  1. Create the hosted Supabase project and choose a plan with backups. Apply the migrations, then enrol the first admin in MFA.
  2. Connect Vercel to the GitHub repository and add the public Supabase settings.
  3. Set up production email (SMTP) so confirmations and the queued notification emails can be sent.
  4. Turn on bot protection on the inquiry form (Turnstile, decision O).
  5. Run the backup and restore drill against the hosted database, and fill in the TODO items in docs/RUNBOOKS.md.
  6. Re-check the known Postgres crash on a function permission error against the hosted image.

Engineering work left

  • Browser tests for the offer, confirmation, submission, review and payment screens. Database tests cover them; a browser run does not yet.
  • Browser check of the notification bell and mark-as-read as an admin.
  • An email sender for the notification queue, once production email exists.
  • A follow-up migration to remove default public execute rights from some Phase 1–3 functions (needs owner approval).
  • A full script Content Security Policy. Only anti-framing is set today.
  • Three metrics can't be worked out from stored data yet: gross contribution, admin time per project and editor drop-off.
  • Small items: the seeded applicant account doesn't sign in, editors can't edit their profile after approval, and the CI actions need updating off Node 20.

Recommended order

  1. Decide KB7, F and KB9. Each one can change what still needs building.
  2. Give the go-ahead (with counsel's view on PDPA) to build E, payout details, before any real transfer.
  3. Set up the hosted environment and run the hosted restore drill.
  4. Settle KB4 and KB5 for the pilot, then the legal and brand items before public launch.
